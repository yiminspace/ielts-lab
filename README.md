# IELTS Lab · 雅思练习室

个人雅思练习应用，支持本地使用和仅本人可访问的在线服务。把自己已有的材料整理为可交互的听力、阅读、词句和口语写作练习，独立保存草稿、收藏、笔记和练习结果。

应用代码与资料分开：公开仓库和镜像只包含原创实现、原创示例、测试与配置密文。真实题库、音视频、录音、作答和明文凭据保存在私有运行环境。

## 在线服务与项目结构

| 内容                           | 位置 / 服务                                                      |
| ------------------------------ | ---------------------------------------------------------------- |
| React + TypeScript + Vite 前端 | `apps/web` / `ielts-web`，容器端口 4317                          |
| Node API                       | `services/api` / `ielts-api`，容器端口 4318                      |
| 对外同源入口                   | `https://ielts.yiminlab.site`，`/api/*` 和 `/media/*` 转发至 API |
| 学习数据                       | PostgreSQL 独立 `ielts_db`，受限运行角色 `ielts_app`             |
| 发布与运行配置                 | `deploy/`、`.github/workflows/`、`secrets/`                      |

前端使用 `@yiminlab/voyage` 的专用 `ielts` 主题与 `@yiminlab/authkit/voyage` 登录组件。
API 验证 AuthKit 身份并核对固定所有者账号，再签发同源 HttpOnly 会话 Cookie；目录、题目、
记录、媒体和录音均在服务端验证访问权限。其他已登录账号也不能访问。运行时不信任浏览器
传入的用户身份头。生产环境缺少认证、数据库或录音存储配置时拒绝启动。

服务部署、SOPS 密钥管理与 CI/CD 见 [部署说明](docs/deployment.md)，数据备份与隔离恢复演练见
[备份说明](docs/backup.md)。公开源码不代表私人数据开放；前端登录守卫不替代服务端授权。
下面的启动命令用于本机模式；生产由 CI/CD 分别发布两个服务。

## 运行

需要 Node.js 22.19 或以上。以下命令均在 `ielts-lab` 项目目录的终端中执行。

### 首次准备

```sh
npm ci
npm run build
```

安装依赖并生成可运行的网页。已有 `node_modules` 和最新 `dist` 时，不需要每天重复这两步。

### 日常启动与停止

```sh
npm start
```

保持终端运行，在浏览器打开 [IELTS Lab](http://127.0.0.1:4317)。日常练习推荐使用这个命令；它读取已构建的网页和已保存的材料配置。没有连接归档时使用原创示例。

如果应用已经运行，直接打开同一个地址，不必再启动一份。结束使用时，在启动它的终端按 `Ctrl+C`。仅关闭网页不会停止本地服务；关闭网页或停止服务也不会暂停限时练习，恢复时仍按原来的开始时间计算剩余时间。

出现 `EADDRINUSE` 或“端口已被占用”时，新启动的程序会退出，不会替你关闭原有程序。若已有运行中的 IELTS Lab，打开它即可；如果该端口由其他程序使用，可以选择另一个未占用端口：

```sh
PORT=4321 npm start
```

此时打开 `http://127.0.0.1:4321`。平时保持同一个地址，便于沿用浏览器中的草稿；更换地址前可先导出记录备份。

### 连接本地归档

只需首次连接或归档移动后执行。选择包含 `data/整理` 和 `data/media` 的归档根目录；路径中有空格时保留引号：

```sh
npm run import -- "/absolute/path/to/archive"
npm start
```

导入将目录关联写入项目内的 `config.local.json`，直接读取现有媒体，不额外复制数 GB 的音视频。配置和索引放在 Git 忽略的本地位置，重启应用后仍然有效。归档目录必须保留；移动后重新导入。如果应用正在运行，先在其终端停止，重新关联后再启动。

### 修改代码时

```sh
npm run dev
```

开发模式自动更新页面，默认网页端口为 `4317`、API 端口为 `4318`；按 `Ctrl+C` 会停止这次启动的两项服务。先停止日常模式，再启动开发模式。默认端口已被其他程序占用时，可指定两个不同的空闲端口：

```sh
PORT=4321 API_PORT=4322 npm run dev
```

代码改完后，重新构建再切回日常模式：

```sh
npm run build
npm start
```

只运行 `npm start` 不会重新构建，因此修改代码后需先运行 `npm run build`。更新代码涉及依赖变化时，先执行 `npm ci`；开发验证可运行 `npm test`。

应用默认只监听当前电脑。网页适配手机屏幕，但这不等于手机已经能远程访问当前电脑；远程访问需要另行配置受保护的部署方式。

## 功能

- A / G 类型：可切换学术类、培训类和全部资料；听说与基础训练共用，读写按已确认的归档类别筛选。包含原创 G 类生活/职场阅读、书信和议论文练习，并提供官方 G 类样题入口。
- G 类整套：从“G 类完整套卷”连续完成听力、阅读和写作；四段听力、三部分阅读、两题写作，分科保存和交卷，可刷新恢复。
- 统一练习工作区：听力、阅读、写作与历史复盘采用接近机考的顶栏、说明条、分栏和底部导航；复盘答案只读，学习工具按需展开。
- 考试练习：从工作区的 Options → 考试练习进入；参照 IDP 官方熟悉测试的英文布局，独立草稿，支持不计时熟悉与单篇限时练习。具体依据与差异见 [参考分析](docs/reference-analysis.md)。
- 听力：答题、题号导航、提交判分、解析、原文和译文、倍速、逐句播放与循环。
- 阅读：原文与题目分栏，填空/选择/判断/匹配，标注、译文、解析、草稿。
- 词汇与句子：发音、卡片、拼写听写、答案对照、静态语法分析。
- 数字与打字：听写核对、输入练习和完成记录。
- 口语：题目播音、计时、浏览器录音、回听和下载。
- 写作：题目、编辑器、字数、计时、草稿与导出。
- 公开课：本地视频/音频与课件图片。
- 资料管理：分类、资料集筛选、搜索、收藏。
- 学习记录：本机持久化、错题练习入口、学习笔记、JSON 备份与恢复。

具体已验证范围和边界见 [功能与验证](docs/coverage.md)。

## G 类整套练习

打开“G 类完整套卷”（`#/papers`），选择试卷后进入 `#/paper/:id`。当前已连接归档有 56 套明确归属的 G 类试卷，55 套满足完整性检查；C8 · Test B 的阅读结构计为 42 分，显示“待核对”并禁用启动。只有材料对应唯一、顺序完整、听力和阅读各 40 分、两题写作以及本地音频齐备的归档试卷才允许启动。

听力四段顺序播放，全部结束后有 2 分钟检查；阅读三部分共用 60 分钟；两篇写作共用 60 分钟，切换题目或刷新不会重新计时。提交一科后进入下一科，最终可以查看各部分记录并导出本次作答。听读按已有答案核对，作文保存正文，不生成考官分数。

未导入归档时也可体验“原创整套流程短样例”：听力 16 题、阅读 18 题、写作 2 题。四个听力部分重复同一段约 17 秒的原创音频；阅读和写作仍各计时 60 分钟。它用于检查操作流程，不是完整题量的试卷。

这是本地练习流程。归档录音中的提示和停顿可能与考场不同；口语仍单独练习，应用不提供考点身份核验、监考或官方成绩。G 类写作总时长与字数要求依据 [IELTS 官方写作格式](https://ielts.org/take-a-test/test-types/ielts-general-training-test/ielts-general-training-format-writing)，听力最后 2 分钟检查依据 [IDP 机考说明](https://ielts.idp.com/canada/prepare/article-how-computer-delivered-ielts-works)。整卷浏览器验收状态单独记录在功能文档中。

## 数据与记录

原归档为只读。服务部署前使用 `npm run export:archive -- /absolute/source /absolute/new-destination`
导出部署资料：保留材料 ID、试卷结构和媒体允许列表，只复制学习文档、允许媒体与最小试卷关联，
移除已知账号字段，不复制整个原软件归档，也不修改原始文件。资料路径只写运行配置，不提交 Git。

在线模式以 PostgreSQL 为记录来源，按作答、草稿、笔记、收藏、设置与练习会话分别保存。
草稿使用版本检查，交卷记录按 ID 幂等，避免跨设备整份覆盖或重复提交。浏览器按已验证账号
缓存未同步输入，冲突时保留本机副本并提示导出；明确选择恢复服务器记录前先下载备份。
数据导入为事务内增量合并，已有记录优先，不因导入覆盖服务器的新作答。

口语录音可上传后长期保存、跨设备回听、下载与删除。上传失败时浏览器 IndexedDB 保留待上传
副本并提供重试和本机下载；浏览器清理存储仍可能移除本机副本。每段录音限制 32 MiB；
JSON 学习记录导出不包含录音文件，服务器备份必须另包含录音目录。

本机模式继续使用浏览器与 `.local/progress-archive.json` / `.local/progress-demo.json`，
两种材料模式隔离。进入“资料与设置”导出记录；本机模式的导入会替换当前本机记录。
迁移前先备份这两个文件，再按 [API 存储说明](services/api/migrations/README.md) 将其幂等导入
指定所有者账号。服务器运行配置与 `.local/` 不随 Git 同步，原始材料需另行备份。

客观题按归档答案核对，不保证特殊答案容错与原平台完全一致；写作和口语保留现有评分边界，
不生成虚构 AI 分数。会话当前适用于单实例：重启后前端重新交换会话，最长一小时且不超过
AuthKit 凭据期限；已签发会话的撤销边界见 [API 说明](services/api/README.md)。

## 实现

React + TypeScript + Vite；Node HTTP 服务负责身份授权、材料、媒体范围请求、录音与学习记录。在线模式使用 PostgreSQL；本机模式保留原子 JSON 保存。富文本经过 DOMPurify 清理。媒体只从指定归档允许列表或仓库原创样例提供，不代理远程地址。

REA 的已有分析结果用于理解 Electron 客户端边界；材料字段、题型与前端可见行为用于确定实现。REA 不会恢复原平台服务器、模型、真人服务或未取得的内容。

## 开发约定

不要把真实材料或用户记录添加到测试夹具。所有可提交示例应为自行编写。`config.local.json`、`.local/`、明文环境文件、私钥、真实媒体与构建结果不应进入 Git。仅提交 SOPS 密文和公钥，构建上下文采用文件允许列表。
